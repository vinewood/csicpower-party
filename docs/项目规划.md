## 一、项目背景与目标

### 1.1 项目背景

中国船舶集团有限公司党校作为集团内部党员干部培训的重要基地，承担着党的建设理论教学、船舶行业发展战略研究、信息导航等重要职能。

当前面临的主要挑战：
- **教学资源分散**：课程设计、课件制作依赖人工，效率低下
- **科研工具匮乏**：论文阅读、文献检索、选题分析缺乏智能化工具
- **信息获取困难**：新闻订阅、政策解读需要人工筛选和汇总
- **AI能力缺失**：现有系统未集成大模型能力，无法享受AI技术红利

### 1.2 项目目标

构建一个**零编译、低成本、高可用**的AI智能业务平台，为党校40名用户（讲师20人、研究员15人、领导5人）提供：

1. **智能化教学支持**：AI辅助课程设计、课件生成、经验萃取
2. **科研效率提升**：论文润色翻译、文献检索、选题推荐
3. **信息自动聚合**：RSS新闻订阅、AI自动摘要、日报生成
4. **技能复用共享**：预置20+科研教学技能，支持自定义创建
5. **视频智能分析**：音视频自动转录、思维导图生成、结构化笔记

### 1.3 成功指标

| 指标 | 目标值 |
|------|--------|
| 用户活跃度 | ≥80% 周活跃 |
| 教学效率提升 | 课件制作时间减少50% |
| 科研效率提升 | 论文处理时间减少60% |
| 系统可用性 | ≥99.5% |
| 用户满意度 | ≥4.5/5.0 |

## 二、技术方案

### 2.1 核心技术栈

**设计理念**：零编译、快速迭代、低成本维护

| 层级 | 技术选型 | 理由 |
|------|---------|------|
| **后端框架** | Python 3.12 + FastAPI | AI生态母语，异步高性能 |
| **模板引擎** | Jinja2 | 服务端渲染，无需前端编译 |
| **前端交互** | Alpine.js 3.x | Vue风格语法，CDN引入零安装 |
| **CSS框架** | Tailwind CSS | 实用优先，CDN即时生效 |
| **组件库** | Flowbite | 基于Tailwind的组件库 |
| **数据库** | MySQL 8.0 | 成熟稳定，兼容性好 |
| **缓存/队列** | Redis + Celery | 异步任务处理 |
| **AI网关** | 阿里云百炼 | Qwen全系 + RAG知识库 |

### 2.2 技术路线对比

**传统路线（已放弃）**：
```
React/Vue + Webpack/Vite  →  需要编译
npm install (500MB+)       →  依赖庞大
修改代码 → 编译 → 刷新     →  反馈慢
TypeScript                  →  学习成本高
```

**采用路线（零编译）**：
```
Jinja2 + Alpine.js + CDN  →  无需编译
零依赖安装                   →  开箱即用
修改代码 → 直接刷新          →  即时反馈
纯JavaScript                →  门槛低
```

**成本对比**：
- 传统路线研发成本：~¥8.5万
- 零编译路线研发成本：~¥7.0万
- **节省成本**：~¥1.5万（18%）

## 三、功能模块设计

### 3.1 六大核心模块

#### 模块一：教学工作台
**对标对象**：aizke搜索界面

**核心功能**：
- 课程设计与管理
- AI辅助课件生成
- 音视频分析工具
- 教学经验萃取
- AI互动课堂

**关键交互**：
- 搜索驱动的主操作区
- 可折叠的侧边AI助手面板
- 功能卡片可拖拽排序

#### 模块二：科研工作台
**对标对象**：AMiner + 维普学术平台

**核心功能**：
- 课题选题助手（AI推荐）
- 文献检索与管理
- 论文润色/翻译/校对
- 研究动态追踪
- 科研项目空间

**关键交互**：
- Dashboard数据概览
- 选题助手 + 文献检索双核心工具并排
- 模型切换按钮常驻

#### 模块三：信息导航台
**核心功能**：
- 多源RSS新闻订阅
- AI自动摘要
- 每日要点简报生成
- 支持导出PDF和分享

**关键交互**：
- 订阅源可管理（添加/删除/启停）
- 右侧面板自动生成日报
- 分类过滤和搜索

#### 模块四：技能中心
**对标对象**：青泥AI技能广场

**核心功能**：
- 预置20+科研/教学/通用技能
- 自定义技能创建
- 技能评分与使用统计
- 个人技能空间管理

**关键交互**：
- 技能卡片网格布局
- 弹窗展示技能详情
- 一键添加到我的技能

#### 模块五：视频分析工具
**对标对象**：dwsj.cn用户体验

**核心功能**：
- 拖拽上传视频
- 自动转录（语音→文本）
- 自动生成思维导图
- 结构化笔记提取

**关键交互**：
- 上传区域支持拖拽
- 处理进度实时显示
- 完成后并排展示结果

#### 模块六：系统管理后台
**核心功能**：
- 用户与角色管理
- AI模型配置
- 用量统计与Token消耗监控
- 系统公告管理
- RSS订阅源管理

## 四、数据架构

### 4.1 多租户隔离策略

**策略**：共享数据库 + `user_id` 隔离

**实现方式**：
- 每个业务表都包含 `user_id` 外键
- 所有查询都必须带 `user_id` 过滤条件
- 支持角色权限控制

### 4.2 核心数据表

1. **users** - 用户表
2. **user_preferences** - 用户偏好表
3. **conversations** - 对话表
4. **messages** - 消息表
5. **projects** - 项目表（科研/教学）
6. **skills** - 技能表
7. **user_skills** - 用户技能收藏表
8. **rss_sources** - RSS源配置表
9. **news_articles** - 新闻文章表

## 五、外部服务集成

### 5.1 集成策略

**核心原则**：不做"合并"，做"桥接"

```
┌─────────────────────────────────┐
│      统一前端（Jinja2 + Alpine.js）   │
├─────────────────────────────────┤
│      统一API网关（FastAPI）         │
├─────────────────────────────────┤
│      外部服务层（独立部署）         │
│  ├─ 阿里云百炼 API              │
│  ├─ DeepSeek API                │
│  ├─ RSSHub (Docker)             │
│  ├─ Miniflux (Docker)           │
│  └─ gpt_academic (Python模块)    │
└─────────────────────────────────┘
```

| AI-Video-Transcriber | 提取引擎 + FastAPI包装 | 1.5人周 |
| RSSHub + Miniflux | 纯API消费，不改代码 | 1.0人周 |

## 七、部署架构

### 7.1 推荐部署方案

**方案**：单机Docker部署

**服务器配置**：
- 云服务商：阿里云ECS
- 实例规格：8C16G
- 操作系统：Ubuntu 22.04 LTS
- 存储：100GB SSD云盘

**架构图**：
```
                    互联网
                       │
              ┌────────▼────────┐
              │   Nginx (80/443) │
              │   SSL 终结       │
              │   反向代理        │
              └───┬──────┬──────┘
                  │      │
       ┌──────────▼─┐  ┌─▼──────────┐
       │ FastAPI App │  │ RSSHub     │
       │ (主应用)     │  │ (Node.js)  │
       │ Port 8000   │  │ Port 1200  │
       └──────┬──────┘  └────────────┘
              │
    ┌─────────┼─────────┐
    │         │         │
┌───▼───┐ ┌──▼───┐ ┌──▼───┐
│MySQL  │ │Redis │ │Celery│
│:3306  │ │:6379 │ │Worker│
└───────┘ └──────┘ └──────┘
              │
    ┌─────────▼─────────┐
    │  阿里云百炼 API    │
    │  (Qwen / RAG)     │
    └───────────────────┘
```

## 八、风险与对策

### 8.1 技术风险

| 风险 | 影响 | 对策 |
|------|------|------|
| gpt_academic GPL许可证 | 合规风险 | 不改源码，仅API调用 |
| 百炼API不稳定 | 服务中断 | 保留DeepSeek直连API作为备用 |
| 视频转录大文件超时 | 用户体验差 | Celery异步队列 + 进度通知 |
| 零编译路线性能瓶颈 | 用户体验 | Alpine.js + CDN性能足够支撑40人 |

### 8.2 项目风险

| 风险 | 影响 | 对策 |
|------|------|------|
| 个人开发进度风险 | 延期 | MVP优先交付核心价值，业务工作台逐步迭代 |
| 用户接受度低 | 项目失败 | 早期用户参与设计，快速迭代反馈 |
| 预算超支 | 项目中断 | 严格控制外包依赖，优先使用开源工具 |
